# AutoResearch 第二代流程｜第四部分：最终方法复验、证据整理、QA 与交付

- 文档版本：第二代（V2）四部分拆分版
- 整理日期：2026-10-02

本部分在外部编排允许收尾后，完成各轨迹最终候选提交、唯一 best_method 选择及干净环境复验，再整理证据、执行最终 QA 与自检，交付六项材料。

## 适用范围与共同约定

- 当前任务固定为 **S1**，本文属于第二代流程的四部分拆分版。
- 读取论文后，任务制作、实验、镜像构建、模型连接测试、研究、验证和打包均在云 GPU 服务器完成。本地仅保存流程文档和按需接收交付副本。
- 依据为用户提供的第二版教程、第二版 example、第二版 QA skills、最终交付清单和用户最新补充要求。QA 决定质检标准，教程指导整体实施，example 仅作结构参考。
- 第一版任务规范不作为依据；前两轮记录仅作低权重流程参考，不继承其中未经验证的实现或完成声明。
- 本文是执行说明，不代表已经完成服务器检查、实验、模型连接或验收。
- 本文件是专家侧工作指南，包含方法来源和证据要求，不得整体作为研究 Agent 的题面或前置上下文；研究 Agent 仅接收经过隔离的公开任务说明。

## 开始前需要的输入

- 第一部分的论文来源、方法选取、固定协议、正式成对实测与模型重载证据。
- 第二部分的双镜像任务、模型连接证据、小规模试跑结论及已解决问题记录。
- 第三部分的两条完整独立轨迹、受保护的有效时长证据和各自最佳候选。
- 用户或授权外部编排发出的收尾决定；两条各至少 10h、目标 11h 的执行情况已核验。
- 所有任务版本与证据对应关系清楚，缺失项或中断如实标注。

## 选择最终方法并独立复验

外部编排确认该轨迹满足时长硬约束、记录要求并发出收尾指令后，执行最佳候选复测，将其及必需产物恢复到 `/workspace/solution`，供 Harbor 移交独立评分。不能由研究模型自行提前进入最终结束状态。

随后，在相同 Public/Dev 口径下比较两条轨迹产生的有效方法，选出唯一最终 `best_method/`：

- 保存完整代码、稳定入口和必要配置。
- 在干净任务快照中重新运行，确认能正常出分。
- 记录选优依据、质量门和复测结果。
- 若最佳方案不能重跑，修复后再验，或选择上一份可复现方法。

`best_method/` 保存最终代码；评分依赖的模型按任务合同随候选移交。它不能直接用专家 Reference 替代。

**阶段产出：**唯一最终方法及干净环境复验记录、明确的选优说明。

## 整理证据、执行最终 QA、自检并打包

### 制作期间的材料组织

| 材料目录 | 职责 |
|---|---|
| `workspace/` | 可执行 Harbor 任务及专家侧 Reference |

| `optimization_evidence/` | 全部正式 Baseline/Reference 结果、原始日志、条件性模型及统计汇总 |

### 专家证据内容

专家证据应包含任务与方法说明、双镜像构建及运行信息、隔离设计、真实实验结果、两条轨迹概况、最终方法选优与复测依据、已知限制。

- `专家作业说明文档.md`：解释任务、运行、评分、隔离、专家过程和已知限制。
- `expert_annotation.json`：精简机读标注，包括任务类型、优化面、指标方向、B/R/U 和隔离关系，不混入运行日志或平台审核结论。
- `run_summary.json`：记录专家自验状态、两个模型组合的实际有效时长、复测和选优依据。
- 两份轨迹：记录真实方法演进，不混入 Baseline/Reference 的训练 seed 证据。
- `optimization_evidence/`：保留全部正式成对实验及统计汇总，不用人工摘要替代原始运行日志。

### 最终检查

最终 QA 先检查 G01–G03，再完成 21 项实现检查、Harbor 六项、格式及跨文件一致性检查。QA15 按 QA skills 的适用范围跳过，不因此省略制作阶段应有的资源验证。

QA skills 默认进行只读静态质检，不在该审查流程中执行提交代码；前述动态验证是任务制作与试跑环节，二者分别记录。

自检 checklist 对每项记录实际状态与证据；不适用项说明理由，未完成项不能填通过。另明确核对本轮用户指定要求：S1、主表 Baseline 来源、论文归一化预筛选及实际 3σ_B、云服务器依赖与双镜像实跑、Agent 管理权限隔离、外部停止控制、逐轮记录及两条实际有效时长。

发现问题后，回到对应阶段修复，重新生成受影响的证据。质检报告保存在待检包之外，避免修改被审查材料。

静态检查不能代替实际运行，专家自验也不能写成平台正式验收通过。正式 Hidden 复现、防作弊审核及最终验收由平台负责。

**阶段产出：**完整材料、最终 QA 结果、自检 checklist 和六项对外交付物。

## 最终对外交付清单

最终交付固定为以下六项：

| 序号 | 交付项 | 内容与用途 |
|---|---|---|
| 1 | **evidence.zip** | 完整证据归档，覆盖专家说明与标注、正式成对实验、方法与复验证据等 |
| 2 | **harbor_task.zip** | 完整可执行任务包，包含题面、配置、Agent 环境、独立 Verifier 及所需任务资产 |
| 3 | **小规模试跑结论** | 对真实试跑结果、问题修复和未验证部分的明确说明 |
| 4 | **Codex + GPT-5.6 Sol Max 轨迹** | 第一条独立、真实、完整的研究过程 |
| 5 | **Codex + Seed 2.1 Turbo High 轨迹** | 第二条独立、真实、完整的研究过程 |
| 6 | **自检 checklist** | 对照第二版要求逐项填写，并关联可核查证据 |

三个材料目录是制作和组织方式；六项清单才是最终对外交付形式。

`交付物.md` 尚未展开两个 ZIP 的精确内部归档边界；打包时需要建立文件映射，保证 Reference、最终方法和全部必需证据都有明确归属、路径可追溯，公开任务内容与专家私有材料保持隔离。表中 ZIP 内容是当前对用途的理解，不作为已确认的逐文件压缩包规范。

## 打包前后的完整性复核

1. 建立服务器上的文件到六项交付的映射，确定每份 Reference、模型、最终代码、轨迹和实验记录的归属；不得在压缩过程中丢失必要证据。
2. 保持两个 ZIP 的路径和引用可追溯。内部边界按已确认的交付规则落实，不能因拆成两个包就把专家私有材料放入 Agent 可见镜像。
3. 脱敏检查不得删改实验事实；交付中不包含凭据、访问令牌或不必要的私人路径。必要大模型产物按任务允许的不可变资产方式交付并记录版本、大小和哈希。
4. 实际列出压缩包内容并在独立位置检查解压后的路径、文件完整性及引用；关键内容变化后重做受影响的验证，不能沿用旧报告声称新包通过。
5. 两份独立交付轨迹与证据包中引用的版本保持一致；小规模试跑结论和 checklist 反映最终交付版本，旧试跑对应旧版本时明确变化及复验情况。
6. 完成六项交付清点后，由专家侧或外部编排决定容器与临时资源处理，先保留可追溯的代码、模型和证据；研究模型无权执行清理。

自检 checklist 至少包含检查项、状态、实际证据位置及待修复内容；“未验证”“不适用”和“不通过”分别标明，不用静态 QA 结果冒充平台 Hidden 验收。
