## 完成双镜像任务封装和隔离

两套镜像均在 **云 GPU 服务器** 上构建、检查和运行；不将本地构建视为服务器可运行的证明。

构建前由专家侧检查服务器现有依赖与能力：

- Docker 客户端与 daemon 是否可用，当前权限是否允许构建、启动和运行两个独立容器；若服务器本身是受限容器，实测是否支持所需能力，不只检查命令是否存在。
- NVIDIA 驱动、容器 GPU 运行支持及 GPU 定向分配是否正常，镜像框架与驱动是否兼容。
- Harbor 目标版本、任务配置解析、独立 Verifier、artifacts 移交和模型接入所需组件是否可用。
- 磁盘、共享内存、CPU/内存、镜像下载、数据下载及运行所需网络条件是否满足任务要求。
- 检查基础镜像及缓存是否可复用，列明“已有且可用 / 缺失 / 版本不兼容”及最小安装或调整动作。

需要新装时在服务器补齐并保留版本和检查结果；已满足要求的组件不重复安装。宿主机装有依赖不代表镜像内具备依赖，Agent 和 Verifier 各自所需依赖仍须在自己的构建环境中完整准备。若当前云服务器不支持真实双镜像运行，应解决服务器能力问题后继续，不能以普通进程试跑冒充双镜像验证。

### 两套独立环境

| 环境 | 构建上下文 | 包含内容 |
|---|---|---|
| Agent 环境 | `environment/` | 公开依赖、Starter、公开数据、Public/Dev 评分入口 |
| Verifier 环境 | `tests/` | 可信评分器、评分依赖、私有资产及候选隔离机制 |

### 题面与机器配置

编写 `instruction.md` 八个章节：

```text
Goal
Task Setting
Objective and Metrics
Allowed Scope
Hard Boundaries
Submission Instructions
Workflow & Iteration
Completion Criteria
```

题面写清输入输出、评分、边界、命令和提交要求，不暴露参考方法、论文标题或仓库答案线索。`task.toml` 与题面保持一致，并配置独立 Verifier 和候选移交。

### 实际运行关系

```text
Agent 在 /workspace/solution 修改方法
    ↓
在 Agent 环境调用 Public/Dev 评分
    ↓
根据公开反馈继续迭代
    ↓
结束前恢复最佳候选和必需模型、配置
    ↓
Harbor 只移交约定的候选产物
    ↓
独立 Verifier 执行 /tests/test.sh
    ↓
可信进程写入 /logs/verifier/reward.txt 或 reward.json
```

隔离不仅是创建两个容器。候选在 Verifier 中仍是不可信代码，不能读取私有标签、参考实现，也不能修改可信评分器和最终 reward。

## 测试两个指定模型的真实连接

### 固定组合与测试位置

| 正式组合 | 必须核实的内容 |
|---|---|
| **Codex + GPT-5.6 Sol Max** | 所需模型访问权限、实际模型标识及 Max 档位映射、Codex/Harbor adapter 配置和真实返回 |
| **Codex + Seed 2.1 Turbo High** | 所需模型访问权限、实际模型标识及 High 档位映射、Codex/Harbor adapter 配置和真实返回 |

测试在云 GPU 服务器完成，并覆盖正式运行实际使用的调用位置、认证方式、网络路径和 adapter。宿主机请求成功不自动等于正式 Agent 调用链成功。

以目标部署版本实际支持的配置核实模型标识和推理档位，不凭显示名称猜测参数。若某模型或档位不可用，记录明确阻塞，不静默替换模型、降档或把默认值当作已生效。

### 连接测试顺序

1. **检查现有调用环境。** 确认 Codex、Harbor adapter、必要客户端、账户或 API 认证是否可用；复用正确环境，仅补齐缺失组件。凭据由可信运行侧提供，不写入题面、公开镜像、日志或交付包。
2. **核对网络和端点。** 验证实际运行位置的 DNS、TLS、代理或网关、服务地址及超时配置；仅测试本任务所需服务，保留脱敏结果。
3. **逐个最小真实调用。** 分别通过实际模型接入链路发起少量请求，确认服务返回有效响应，检查模型、档位映射、错误信息及可用请求标识。不能仅凭配置文件存在、端点可达或 HTTP 状态码就判定模型完整可用。
4. **验证实际 Agent 工具闭环。** 每个模型分别在独立短程试跑环境中读取公开任务说明，执行合法工具调用，运行公开评分入口，并生成可解析的轮次记录。单次文本回复不能证明 Coding Agent 能实际工作。
5. **核对并发条件。** 如果第三部分采用两条并行运行，在相同部署方式下做最小并发检查，确认限流、资源分配和输出目录不会互相干扰；若顺序运行，记录安排并保持共同资源规则一致。
6. **形成连接结论。** 分别标记“已通过 / 失败 / 未验证”，附真实证据；配置或网络条件变更后复测受影响链路。

模型连接检查与短程试跑均不计入第三部分正式长程研究的有效时长。短程试跑输出单独保存，正式两条研究从干净 Starter 和独立空输出目录开始。

### 连接证据至少包含

- 测试时间、任务版本、服务器和实际调用位置的非敏感标识。
- Codex/Harbor/adapter 版本，指定模型及档位配置和生效核验依据。
- 脱敏请求结果、有效响应或错误、耗时与可核对的日志位置。
- 工具调用、Public/Dev 出分与记录落盘是否成功。
- 发现的问题、修复动作、复测结果及尚未解决的限制。

无法从服务返回中直接验证的配置，应说明依据和未验证范围，不猜测实际后台模型或档位。

## 为第三部分配置外部编排

长程研究开始前，应准备并在小规模试跑中验证：

- 两条独立环境、输出目录及共同任务/资源配置。
- 研究用户的受限权限；不提供宿主机管理权限、Docker 控制 socket、容器管理工具或另一条轨迹。
- 编排进程位于研究 Agent 控制范围之外，负责调度、恢复、计时、记录监督及停止决定。
- 每条有效研究最低 10h、目标 11h；总墙钟预算覆盖开销、阻塞和最终复测。
- 模型提前返回时继续调度，基础设施故障时保留证据并由外部恢复；中断不能自动转成完成。
- 逐轮八字段、评分原始输出、有效/排除时间区间及持久化证据的检查机制。

详细执行规则见第三部分；本部分先证明这些机制能工作，不能只写进 Prompt。


## 进行小规模试跑，形成独立结论

在启动长程 Agent 前，实际验证整个任务是否可用：

- 两套镜像都能构建，依赖和路径正确。
- Starter 能在 Agent 环境获得 Public/Dev 分数。
- 短程 Agent 能修改方法、调用评分并理解反馈。
- 候选及必需产物可以正确移交。
- 独立 Verifier 能实际评分并写入 Harbor 可读取的 reward。
- 失败分类、冻结文件保护和关键约束确实生效。
- 运行时间、资源消耗和反馈质量适合继续迭代。
- 外部编排能记录有效工作时长，检测模型提前返回并继续调度；模型无法修改计时记录、关闭编排、停止或删除容器。
- 每轮八字段记录、原始评分输出、时间记录和轨迹落盘机制能够相互核对。缺失记录必须被发现，不能静默进入长程运行。

若无正式 Hidden 权限，使用授权自验数据验证链路，明确正式 Hidden 尚待平台复核。

形成最终清单中的 **“小规模试跑结论”**：写明测试版本、实际执行内容、结果、发现的问题、修复情况和仍未验证的部分。

结论须有运行证据支持。小规模试跑不能替代正式实验或长程轨迹；本流程不自行增加未声明的固定试跑时长或轮数门槛。

**阶段产出：**小规模试跑结论及对应真实运行证据。
