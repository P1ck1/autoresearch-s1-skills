# S1 1：论文与方法标定（完整工具包）

## 固定规则

这是专家侧 S1 工具包，不得整体放进研究 Agent 镜像或上下文。只使用用户第二版资料及最新要求；第一版任务规范不适用。读论文后实际制作、实验、连接、研究与打包均在云 GPU 服务器。本地编写/校验 Skill 不是正式实验。

四阶段通过服务器专家侧 `expert_evidence/阶段交接.md` 衔接。复用已核实工作；调用某阶段不自动启动后续阶段，用户已授权整套流程时可继续，无须重复确认。未获资源信息或访问凭据只询问必要缺口，不自行租机或无限追加费用。

本文优先保留关键决策；进入相应步骤时按下面路由读取参考。模板是空输入，不是已通过证据。脚本输出只代表其标明的检查范围，不代替真实研究、公平性复核或平台验收。

## 执行路径

1. 阅读 [方法与协议](references/workflow.md) 的主表选择和实测要求。Reference 通常是论文方法；Baseline 从主表其他被比较方法选取。论文成绩归一化须在 [0.15,0.8]，U 有依据；缺 σ_B 标为待实测。
2. 在云 GPU 服务器核对代码/数据/资源，固定协议与全部正式 seed，完成实现、短程检查和真实成对实验。方法接口必须允许真实方法更新，不扩展成开放式优化面搜索。
3. 阅读 [证据输入合同](references/evidence-contract.md)，按 [输入模板](assets/paired-input.json) 关联原始 result 的路径、哈希和指标字段；执行 `python3 scripts/paired_stats.py INPUT --root EVIDENCE_ROOT --out REPORT`。脚本核算 n−1 标准差、同 seed、改善、3σ、归一化，不加载模型或执行提交。
4. 训练型每轮保存实际模型、artifact.json、原始日志和干净进程重载；完整留存失败。G01/G02/G03 还须按真实实现与日志语义复核，不能用脚本 PASS 替代。
5. 按 [交接模板](assets/handoff.md) 更新阶段状态、真实命令和路径，交付完整 optimization_evidence、任务实现和论文/代码/任务差异。下一阶段为 `$autoresearch-s1-package`，本阶段不启动正式研究。

数值边界：Reference 实测归一化 [0.15,0.8]；随机评估 Δ≥3σ_B，3–5σ_B 可接受并建议复核，≥5σ_B 强证据。至少三次，正式协议更多则全交。确定性不设通用 5% 规则。U 不事后调来过线，评分不裁剪。

## 验证与完成

执行 `python3 -m unittest discover -s tests -v` 校验工具。真实任务完成需要可追溯的全部成对运行与语义质量门；测试夹具或论文成绩不能代替。完整阶段细节按需读 [流程原文](references/flow-detail.md)。
