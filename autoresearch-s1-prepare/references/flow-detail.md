## 接收论文与任务信息，确认制作边界

当前任务已确定为 **S1**，不再重新选择 S1/S2/S3 模式。收到论文后，先阅读论文和补充材料，确认主实验、论文方法及被比较方法；随后所有实际任务工作转到云 GPU 服务器完成。

需要明确：

- 任务编号及 S1 任务卡的具体要求。
- 代码版本、数据来源、许可及可访问性。
- 云 GPU 服务器的连接方式、工作目录、GPU 型号和数量、CPU、内存、磁盘、网络及预算；实际探测后记录，不依据机型宣传推定。
- 目标 Harbor 版本、运行环境及平台提供的接口。
- 任务卡是否指定数据集、指标、变体或其他约束。

**阶段产出：**任务信息和来源记录。缺少的信息如实标注，不能把示例资源数值直接当成本题要求。

服务器由专家侧制作与编排流程管理。后续两个研究 Agent 仅进入各自受限的任务环境，不继承服务器管理权限。本文只规定执行流程，不表示已连接或检查任何服务器。

## 从论文主表选取 Baseline 和 Reference

不再把大量精力用于开放式选择优化面。直接围绕论文已定义的任务和主实验，确定两种方法，再将其方法差异落实到任务允许修改的接口。

### 方法来源

- **Reference：**一般采用论文自己提出的方法，明确对应主表中的版本及可用实现。
- **Baseline：**从论文主表中除论文自身方法以外的被比较方法中选择一个。不能任意另造弱方法或使用故障、少训练结果来满足分数要求。
- 采用同一数据集、同一任务设置和同一指标下可比的主表数值；记录表号、行列、指标方向、单位、实验设置及方法来源。不能拼接不同设置下的成绩。

### 先用论文成绩计算归一化分数

设论文报告的两种方法成绩为 B_paper 和 R_paper。确定有依据、与指标方向一致的 U_paper，并记录来源；无法可靠估计可达上限时，按教程使用可适用的指标理论上限，不能自行编造上限。

```text
越大越好：S_paper = (R_paper − B_paper) / (U_paper − B_paper)
越小越好：S_paper = (B_paper − R_paper) / (B_paper − U_paper)
筛选范围：0.15 ≤ S_paper ≤ 0.8
```

先统一百分数、小数及其他单位；U_paper 必须位于改善方向且分母非零。仅有 B_paper 和 R_paper 不能唯一确定归一化分数，还需要可信的 U_paper。

选定的 Baseline/Reference 在论文成绩上的计算结果必须落入该区间。若不满足，在主表其余可比对照中重新筛选；若没有可行组合或无法确定 U_paper，应明确问题，不通过随意修改上限、指标或数据集制造达标。

### 同时检查 3σ_B 条件

```text
越大越好：Δ_paper = R_paper − B_paper
越小越好：Δ_paper = B_paper − R_paper
要求：Δ_paper ≥ 3σ_B，且改善为正
```

σ_B 指 Baseline 原始指标多次运行的样本标准差（n−1），不是标准误、Reference 标准差或两个方法差值的标准差。3–5σ_B 可接受并建议复核，≥5σ_B 为强证据。

如果论文提供对应的完整逐次结果，可复算；若只给均值与误差条，先核对误差条定义和运行设置。没有可用的 Baseline 标准差信息时，标记“3σ_B 待服务器实测”，不能由两条平均成绩推算、假定 σ_B=0 或直接声称通过。若评估确为确定性，按 QA 的不适用规则说明依据，仍检查真实改善及归一化范围。

### 论文筛选与最终验收分开

论文成绩用于选择方法组合。后续必须在云 GPU 服务器按本任务固定协议实际运行 Baseline/Reference，重新计算实际归一化成绩及 3σ_B；论文成绩不能直接充当本任务实验记录。

选定方法后，只做必要的任务接口核对：输入输出清楚、可程序化评分、允许合法的方法更新、资源内可反复实验，并保留进一步改进空间。G01 等 QA 门槛继续适用，但不再开展无边界的优化面搜索。

**阶段产出：**选定的主表 Baseline、论文 Reference、来源及成绩对照表、归一化计算、3σ_B 初核或待测说明，以及据此定义的允许修改范围。

## 固定任务协议和四类方法的角色

在正式实验前，固定数据版本及切分、预处理、指标方向、质量门、资源预算、正式 seed 集合、训练与评测流程、checkpoint 选择规则及提交接口。

四个对象必须分清：

| 对象 | 作用 |
|---|---|
| Starter | Agent 的起点，可以是合理朴素实现或接口骨架 |
| Baseline | 支撑改进主张的正式对照，必须正确、合理、公平 |
| Reference | 专家实现的合法改进，用于证明可解并标定难度 |
| best_method | 两条 Agent 轨迹中最终选出且复验成功的方法 |

本任务的正式 Baseline 先按本部分的选取规则从论文主表选定，再将其实现作为默认可运行 Starter；归一化锚点 B 绑定该正式 Baseline 的实际聚合结果。如果 Starter 仅给骨架，仍需提供该选定 Baseline 的独立可执行实现，说明与起点及锚点的映射，不能换成另一种更弱方法。

比较协议要预先确定，不能看到结果后再挑 seed、改评价集、换指标或修改锚点来制造达标。

**阶段产出：**明确且可执行的任务与实验协议，以及 Starter、Baseline、Reference 的角色和映射说明。

## 实现最小可运行链路，并完成技术检查

在云 GPU 服务器先检查现有环境，复用满足要求的组件，仅安装或补齐缺失、不兼容的依赖。记录系统、GPU 驱动、可用 GPU、Python/框架版本、数据存储和运行环境；项目依赖使用独立环境或镜像，避免无依据覆盖服务器已有依赖。

在服务器准备固定版本的数据、依赖和代码，实现：

- Starter/Baseline。
- 专家侧 Reference。
- Public/Dev 评分入口。
- 正式评分器及约束检查。
- 稳定的候选提交接口。

先做小样本、短流程检查，确认数据读取、训练或计算、推理、指标、模型保存与重载均正常，再进入完整正式实验。

这些技术检查用于发现实现错误，**不能作为正式 Baseline/Reference 成绩或长程研究证据**。

**阶段产出：**可运行的最小任务实现，以及真实技术检查记录。

## 完成正式 Baseline/Reference 实验和评分标定

在云 GPU 服务器按照固定协议运行从论文主表选定的 Baseline 与论文 Reference 的全部正式成对实验，保存真实原始结果。以本任务实际结果重新核验论文筛选阶段的归一化区间与 3σ_B，不能用论文数值替代实测。

### 三项核心质量门

| 质量门 | 要证明的内容 |
|---|---|
| G01 方法优化空间 | 接口和实际调用链允许真正的方法更新 |
| G02 Baseline 合理性 | 实现正常、配置合理、训练与预算公平、选择过程完整 |
| G03 提升充分性 | Reference 有真实、足够且可复现的改善，并保留后续空间 |

### 正式实验要求

- Baseline 与 Reference 使用相同正式 seed 集合，逐 seed 配对，保留全部正式运行和失败记录。
- 训练型任务按协议独立训练；不能重复评测同一个已训练模型来冒充多次独立训练。合法共享预训练起点时，须明确声明并遵守正式协议。
- 每个训练模型保存实际产物、哈希和来源，并在干净进程中重载复评分。
- 随机评估未另定次数时至少独立运行 3 次，波动较大时至少 5 次；正式协议规定更多则全部执行。
- 改善至少达到 Baseline 原始指标样本标准差的 **3σ_B**；3–5σ_B 可接受并建议复核，达到 5σ_B 是强证据。
- 确定性评估需要真实正向改善，不额外套用统一百分比门槛。
- 比较应使用一致的数据、评测口径及共同资源约束。若轮数、架构或容量本身是允许的研究变量，应按共同预算及必要匹配控制判断公平性，不机械要求所有配置相同。

### 评分设计

评分采用合理的 Baseline 锚点 B 和预计可达上限 U：

```text
原始指标越大越好：score(x) = (x − B) / (U − B)
原始指标越小越好：score(x) = (B − x) / (B − U)
```

评分必须连续、单调、不裁剪；Reference 的归一化分数应在 **[0.15, 0.8]**。U 需要有依据，不能为使 Reference 达标而事后随意调整。

Public/Dev 与正式评测的数据切分及对应锚点按协议分别固定，不能把 Dev 分数当作 Hidden 分数。

**阶段产出：**完整的 `optimization_evidence/`。如果核心质量门不成立，应返回任务设计或实现阶段修正，再重跑受影响的实验。
