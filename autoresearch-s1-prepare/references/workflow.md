# S1 第一阶段：论文、方法选择与实测标定

把论文转为可交给第二阶段封装的任务实现和真实实验材料。收到执行请求后落实文件与运行，不止提供计划。当前任务固定为 S1；读论文后，数据、代码、实验与后续制作均在云 GPU 服务器完成。

## 依据、角色和阶段边界

- 使用用户第二版教程、第二版 example、第二版 QA skills、六项交付清单和最新补充要求。第一版规则不适用；前两轮记录仅辅助理解流程。
- Reference、论文来源、正式成对结果和本 Skill 属专家侧信息，不得复制到研究 Agent 的题面、镜像或上下文。
- 这一阶段不开展双 Agent 长程搜索，不生成其未来轨迹或 best_method。单独调用本 Skill 时完成本阶段并交接；用户已授权完整流程时可继续下一阶段，无须重复请求已有授权。
- 本 Skill 不依赖旧的准备 Skill。详细流程见 第一部分（原文件身份见 sources.json；核心要求已收入本包）。路径变化时定位当前版本，不凭旧记忆替代。

## 开始与连续交接

先查现有材料，不重复已核实的工作。确认论文及补充材料、任务 ID、官方代码/数据版本、云服务器连接和工作目录、资源预算、目标 Harbor 版本。仅对影响下一步的缺失信息提问，同时推进不依赖该信息的工作；不自行购买或扩容云资源。

在服务器专家侧维护 `expert_evidence/阶段交接.md`，供四个 Skill 顺序使用。这是内部交接附件，不是第七项交付，也不改变平台 JSON schema。至少记录：任务及服务器目录、有效规范位置、代码/数据/协议版本或哈希、阶段状态、真实运行入口和证据路径、未完成项、下一阶段输入。不要写密钥；远程路径不能伪写成本地已存在文件。

先读论文、主表、方法与实验细节，再在服务器核对发布代码与数据。记录论文设置、官方实现和本任务设置之间的关键一致或差异；不得把适配结果声称为逐项论文复现。

## 从主表选方法

1. Reference 一般选论文提出的方法，明确具体版本。Baseline 从主表中除论文自身方法以外的被比较方法中选一个。围绕这两种方法落实可改接口，不开展开放式优化面搜索。
2. 只比较同数据集、同任务设置、同指标的成绩。记录表号、行列、方法、数值、单位、指标方向及实现来源。
3. 用论文 B、R 与有依据的 U 预筛选：

   ```text
   maximize: S = (R - B) / (U - B)
   minimize: S = (B - R) / (B - U)
   0.15 <= S <= 0.8
   ```

   单位先统一，U 在改善方向且分母非零。不能只凭 B/R 两个数确定 S；无法可靠估计 U 时仅在适用时采用理论指标上限，写明依据。不能为过线改变 U、数据集或指标。
4. 同时核对改善 Δ：maximize 为 R-B，minimize 为 B-R，须为正；随机评估要求 Δ≥3σ_B，3–5σ_B 可接受并建议复核，≥5σ_B 是强证据。σ_B 是 Baseline 原始指标样本标准差（n−1），不能用标准误、Reference 方差或配对差标准差替代。
5. 论文有逐次数据则复算；误差条先核实定义。没有可用 σ_B 时记“待服务器实测”，不能由均值编出方差或视作零。确定性评估须说明依据；固定 seed 或样本方差为零不自动证明确定性。
6. 无符合归一化区间的可比组合时记录结果，检查同主表其他合法对照；仍无可行组合则报告具体阻塞，不制造弱 Baseline。

论文分数只作方法选择。最终验收必须使用本任务协议下的实测 B/R。

## 固定协议并实现

- 固定真实数据版本和 Train/Public/Dev/Hidden 边界、预处理、指标方向、质量门、正式 seed 集、重复次数、预算、checkpoint 选择规则、允许修改的接口与提交合同。Dev 不作为训练集。
- 默认将选定 Baseline 实现为可运行 Starter。若只给 scaffold，专家侧仍提供选定 Baseline 的独立入口和映射。评分零点必须绑定该正式 Baseline 的聚合实测，不另设更弱锚点。
- 将论文方法实现为专家侧 Reference，只在允许的方法接口内改动。G01 仍要求实际可表达方法变化，不能只开放固定数字；保留至少一个题面未直接提示的合法后续方向。
- 探测服务器现有 GPU、驱动、Python/框架、资源和依赖；复用满足条件的环境，只补齐缺失或不兼容项。项目依赖用独立环境，不能无依据破坏共享环境。
- 在服务器实现 Starter/Baseline、Reference、公开评分、可信正式评分与约束逻辑。单次修改到出分尽量不超过两小时；必要压缩应明确且对双方公平。
- 先用少量样本检查训练/计算、推理、指标、保存和重载，再运行正式实验。smoke 不作为正式分数或多 seed 证据。

## 成对实验与证据

使用共同数据、评测规则和资源约束。训练策略、轮数或容量是声明的研究变量时按共同预算及匹配控制比较，不机械要求所有配置相同。

正式 seed 全集预先声明并逐 seed 配对，全部保留；随机评估未规定次数时至少 3 次，波动大至少 5 次。训练型任务独立训练，合法共享预训练起点要声明；重复评测同一完成模型不能冒充独立训练。失败和较差结果如实保留，不挑最好 R 或最差 B。

在服务器生成：

```text
workspace/harbor_task/                 # 待第二阶段完成双镜像封装
workspace/reference/                   # 专家参考实现
optimization_evidence/
  训练证据说明.md
  baseline_runs/seed_<真实seed>/
    result.json
    run.log
    model/                             # 仅训练型
      实际checkpoint
      artifact.json
      reload.log
  reference_runs/seed_<真实seed>/       # 与 Baseline 同结构
  comparison_summary.json
expert_evidence/阶段交接.md
```

`result.json` 记录 role、真实 seed、方法/依赖哈希、协议、训练设置、真实命令与执行信息、原始指标、质量门和产物路径；保留原始 stdout/stderr。训练模型记录格式、大小、SHA-256 和来源，在干净进程重载复评分。非训练任务不建空 model/。未知历史字段填 null 并说明，不能反推造记录。

汇总使用全部正式有效运行，复算均值、Baseline 样本标准差、逐 seed 改善、Δ及归一化，明确失败和有效性。实际评分连续、单调、不裁剪，B=0、U=1，Reference 在 [0.15,0.8]；超过 U 可以得分大于 1。Public/Dev 与正式评测各按协议标定，不混用成绩。
