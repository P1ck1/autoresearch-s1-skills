# AutoResearch 第二代流程｜第三部分：外部编排控制下的双模型独立长程研究

- 文档版本：第二代（V2）四部分拆分版
- 整理日期：2026-10-02

本部分使用第二部分已验证的任务、模型连接和外部编排，在云 GPU 服务器完成两条独立长程研究。每条至少 10h 有效研究，实际目标为 11h；研究模型不具有自行停止或容器管理权限。

## 适用范围与共同约定

- 当前任务固定为 **S1**，本文属于第二代流程的四部分拆分版。
- 读取论文后，任务制作、实验、镜像构建、模型连接测试、研究、验证和打包均在云 GPU 服务器完成。本地仅保存流程文档和按需接收交付副本。
- 依据为用户提供的第二版教程、第二版 example、第二版 QA skills、最终交付清单和用户最新补充要求。QA 决定质检标准，教程指导整体实施，example 仅作结构参考。
- 第一版任务规范不作为依据；前两轮记录仅作低权重流程参考，不继承其中未经验证的实现或完成声明。
- 本文是执行说明，不代表已经完成服务器检查、实验、模型连接或验收。
- 本文件是专家侧工作指南，包含方法来源和证据要求，不得整体作为研究 Agent 的题面或前置上下文；研究 Agent 仅接收经过隔离的公开任务说明。

## 启动前检查

- 第一部分的方法与协议、第二部分的双镜像任务版本保持一致；受影响的变更已经复验。
- **Codex + GPT-5.6 Sol Max** 和 **Codex + Seed 2.1 Turbo High** 均已通过实际接入测试。
- 独立 Verifier、候选移交、Public/Dev 评分、原始证据保存及外部计时均已在小规模试跑中验证。
- 两条从干净 Starter 启动，使用同一版本题面和共同资源规则，独立输出目录；不读取短程试跑候选、专家 Reference、另一条轨迹或 Hidden 结果。
- 编排能控制生命周期、监督记录并恢复异常；有效时间和停止决定不由研究模型控制。

## 运行两个指定模型的独立长程研究

### 固定模型组合

| 轨迹 | 模型与推理档位 |
|---|---|
| Codex 轨迹 | **Codex + GPT-5.6 Sol Max** |
| Seed 轨迹 | **Codex + Seed 2.1 Turbo High** |

两条轨迹均在云 GPU 服务器运行，使用同一任务版本、公开评分协议和资源配置，分别从干净环境和独立空输出目录开始。不能互看轨迹、最佳方案、Reference 或专家证据包。

### 研究闭环

每条轨迹执行真实研究闭环：

```text
提出方法假设 → 修改实现 → Public/Dev 评分
→ 分析结果 → 保留或回退 → 决定下一轮
```

本任务按用户要求执行：**每条至少 10 小时有效研究是硬约束，实际计划以每条 11 小时有效研究为目标。** 两条单独核算，不相加；不启用 7 小时例外。11 小时是执行目标，10 小时是最低验收线，达到任一时间点都不赋予模型自行结束的权限。

排队、安装、构建失败、故障恢复和长时间阻塞不计入有效时长。启动器的总墙钟预算必须容纳目标有效研究时长、可预见开销和最后复测；不能把进程存活时间或超时配置直接当作已完成的有效研究时长。

容器稳定存活至少 12 小时是另一个环境目标，不能替代 Agent 的有效研究时长。

### 权限、生命周期与停止决定

两个研究模型没有完全控制权。其研究自主权只限于已出好的题目内执行“提出方法假设 → 修改实现 → Public/Dev 评分 → 分析结果 → 保留或回退 → 决定下一轮”，并履行规定的记录义务。

- **任何理由都不能由模型自行决定终止研究。** “表现已足够好”“已经收敛”“没有必要继续”“时间已到”或发出最终回答，都不是模型获准停止工作的依据。
- 模型不能停止、删除或重建容器，不能关闭宿主机、结束编排服务、修改总时限、改变计时规则或降低记录要求。
- 模型不能改变题目、正式协议、数据边界、质量门或评分器；研究修改仅限题面允许范围。
- 单轮失败时，模型记录原因并继续在允许范围内调整；遇到基础设施故障，交外部编排处置并保留现场，不能将“无法推进”自行认定为研究已完成。
- 是否进入最终复测和收尾，由用户或用户授权的外部编排依据固定规则决定。到达计划时长后也应先核验有效时间和记录完整性，再发出收尾指令。
- 容器停止和清理由专家侧或外部编排负责，须先完成必要复验、候选移交与证据保存。用户明确中止、预算限制或基础设施异常造成的中断如实记录，不冒充完成。

这些限制必须由权限和编排实现，不能仅写在 Prompt 中：研究环境不提供宿主机管理员凭据、Docker 控制 socket 或容器管理工具；使用非特权任务用户及受限文件权限；计时、调度和受保护日志由研究进程之外的组件维护，模型不能修改。

模型主动返回或研究进程意外退出时，外部编排应记录事件、排除无效空档，并从该轨迹已有合法状态继续调度；不得因此直接判定任务完成。故障恢复与重启由外部处理，不能混入另一条轨迹或私有参考信息。无法恢复时标记中断及证据缺口。

### 每轮记录、有效时长与轨迹必须完整

每轮按教程记录八个字段：

```text
round、policy_name、method_summary、status、
score、failure_reason、retained_best、time
```

`score` 使用真实 Public/Dev 原始指标；未成功出分填 `null`。模型组合、有效时长和迭代概况写入运行摘要。Hidden 不作为本次运行中反复调优的反馈。

记录要求由外部编排监督，不能交由两个模型自行决定是否记录：

1. 每轮结束必须持久化八字段记录，包括真实失败轮；保留原始评分输出及足以核对方法变化的过程记录，不只保留最佳轮。
2. 外部检查字段、轮次顺序、时间、评分来源和最佳标记的一致性。缺失时及时要求补全可核实的信息，不能在事后编造分数、时间或方法。
3. 每条运行单独保留开始、继续、暂停、恢复、退出和结束事件，以及有效区间、排除区间、原因和证据。模型自报“已工作若干小时”不能代替计时依据。
4. 单条轨迹的有效时长按有证据支持的研究与实验区间并集累计，重叠实验不重复计时，不能只用 GPU 忙碌时间或最后时间戳减开始时间计算。允许的训练、评分属于研究闭环的一部分；故障阻塞、无任务空转等须排除。
5. 正式轨迹保持教程八字段结构；外部详细事件和时间证据单独保存并在专家说明中引用，运行摘要写入实际有效时长与迭代概况，不擅自扩展平台固定 schema。
6. 收尾前核验两条各至少 10h、以各 11h 为执行目标的情况、记录完整性和最终复测状态；未达到最低有效时长或记录无法核实，不能填写完成。

**阶段产出：**两条独立完整轨迹、各自实际有效时长与研究过程证据、各自保留的最佳候选。

## 交给第四部分的材料与收尾条件

| 材料 | 交接要求 |
|---|---|
| 两条完整轨迹 | 对应指定模型和档位，全部真实轮次、失败记录与八字段结构可核查 |
| 时长证据 | 每条独立有效区间、排除区间、原因和事件；实际至少 10h，记录 11h 目标执行情况 |
| 公开评分记录 | 原始输出与轮次、方法变化、保留或回退决定可对应 |
| 各条最佳候选 | 完整代码、必要配置及任务合同要求的产物，保留对应来源 |
| 运行版本记录 | 任务、镜像、模型接入及有效配置；说明任何异常恢复或中断 |
| 外部收尾决定 | 用户或授权编排核验时长和记录后发出的收尾依据 |

两条轨迹的完成状态分别核验。尚未达到最低时长、缺少不可核实记录或异常中断时，不填写“完成”；模型认为分数足够好不能作为停止理由。

达到条件后，由外部编排转入第四部分，安排最佳候选复测、恢复提交目录及独立 Verifier 评分。模型不能自行退出、停止容器或删除运行现场；候选与证据完成移交前由外部保管。
